RealHand FFG Glove#

The Linux RealHand FFG Glove plugin reads one or two gloves over USB serial and publishes each glove as a standard 26-joint OpenXR hand_tracker. It discovers serial ports and baud rates, queries the firmware-reported side, and reconnects after a disconnect. Either side can operate alone; a missing glove does not control the opposite hand.

Data flow#

FFG USB -> calibrated human skeleton -> HandInjector -> HandsSource -> HandInput retargeter
        21 angle sensors               26 OpenXR joints                any robot hand

The serial protocol follows the Apache-2.0 RealHand FFG Glove pure-Python SDK. The plugin implements the protocol directly in C++, so the Python SDK is not redistributed or required at runtime.

The primary device paths are /hand/left and /hand/right. They are consumed by HandsSource and the same HandInput retargeters used for optical hand tracking, including DexHandRetargeter, Sharpa, and Wuji. The device plugin contains no robot-specific retargeting. Human joint poses are estimated from glove angles and approximate hand dimensions.

Build#

The optional plugin is disabled by default. Enable it explicitly in the source build:

$ cmake -S . -B build -DBUILD_PLUGIN_REALHAND_FFG_GLOVE=ON
$ cmake --build build --target realhand_ffg_glove_plugin
$ cmake --install build --component realhand_ffg_glove

The serial backend requires a POSIX system. Install Isaac Capture using 4. Install the isaaccapture pip package before installing the RealHand example.

USB permissions#

The current user must be able to open the glove’s serial device. On Ubuntu, add the user to the dialout group, then log out and back in:

$ sudo usermod -aG dialout "$USER"

Do not run Isaac Capture as root. Check permissions with ls -l /dev/ttyUSB* and membership with id -nG.

Retargeting and calibration#

Human skeleton calibration describes the device, not a target mechanical hand. One calibration can feed any compatible HandInput retargeter. Wear the glove in its final fit. The command-line workflow waits for Enter before every step, then gives 8 seconds to release the keyboard and prepare, followed by a 6-second hold. It requires at least 120 samples per hold. Change --prepare-seconds, --hold-seconds, or --samples if needed.

Capture these five endpoint poses for each connected side:

  • Open palm: wrist neutral, palm flat, four fingers straight and together; thumb points sideways.

  • Full fist: curl the four fingers fully; keep the thumb outside the fist, without forcing it.

  • Thumb-only curl: keep the four fingers straight; fully bend the thumb MCP and IP joints.

  • Thumb opposition: keep the four fingers straight; sweep the thumb across the palm toward the little-finger base, without forcing fingertip contact.

  • Finger spread: keep the fingers straight and spread them sideways as far as comfortable.

Then lightly touch the thumb tip to the index, middle, ring, and little fingertip, one at a time. Keep the unused fingers relaxed, without squeezing. Release and repeat each of these four contacts, then repeat the original open palm pose. This is one 14-step calibration sequence; when both sides are selected, do the same pose with both hands. The PC calibration window in the hand demos uses this same sequence, sample reduction, and fitting. Consuming robots reuse the human calibration without a model-specific step.

Calibration requires NumPy and SciPy in the Isaac Capture interpreter. Fingers remain independently driven; contact poses are used for calibration, not runtime snapping.

Capture a calibration from the standard DeviceIO stream:

$ uv pip install -e ./examples/realhand_ffg_glove
$ python -m isaaccapture_examples.realhand_ffg_glove.realhand_ffg_glove_calibration \
    --side both \
    --plugin-path install/plugins \
    --realhand-ffg-glove-ports=/dev/ttyUSB0,/dev/ttyUSB1 \
    --output /path/to/ffg_human.yml

Use --side left or --side right when one glove is connected. A later run for the other side updates the same YAML and preserves the existing side. Pass the resulting path with --calibration=/path/to/ffg_human.yml when starting the plugin, or --calibration /path/to/ffg_human.yml when starting the human-skeleton viewer. Without calibration the plugin publishes raw sensors for capture but no active human hand. Recalibrate after re-wearing, power-cycling, or materially shifting a glove. Failed captures leave the previous calibration intact. Files use realhand-ffg-glove-human-calibration-v1; robot-specific calibration files are incompatible. The demo loads existing human calibrations, including those used before CTS, without refitting or rewriting them. Calibration itself does not certify CTS conformance.

Run#

Start the CloudXR runtime, source its OpenXR environment, and launch the installed plugin:

$ python -m isaaccapture.cloudxr.service start
$ source ~/.cloudxr/run/cloudxr.env
$ ./install/plugins/realhand_ffg_glove/realhand_ffg_glove_plugin \
    --calibration=/path/to/ffg_human.yml

Automatic discovery only probes /dev/serial/by-id/ entries whose names contain RealHand, RealForce, or FFG (case insensitive). A generic USB UART identifier does not distinguish a glove from other hardware. For these devices, explicitly select the verified glove ports:

$ ./install/plugins/realhand_ffg_glove/realhand_ffg_glove_plugin \
    --calibration=/path/to/ffg_human.yml \
    --ports=/dev/ttyUSB0,/dev/ttyUSB1 \
    --baudrates=2000000,460800

Use only verified glove ports and close other applications reading the same devices.

When the calibration command starts the plugin with --plugin-path, pass --realhand-ffg-glove-ports=/dev/ttyUSB0,/dev/ttyUSB1 to select its ports. Diagnostics and the Isaac Sim human-skeleton viewer instead accept --ports. If the plugin is already running separately, omit --plugin-path instead of starting another process on the same ports.

The supplementary collections realhand_ffg_glove_left and realhand_ffg_glove_right publish sensor_0 through sensor_20 in radians. These JointStateSource inputs are for calibration and diagnostics, not robot control. Mechanical hands consume the standard human skeleton through HandsSource.

Wrist placement#

The plugin uses the shared WristPoseSource utility, as in the Wuji Glove plugin. --wrist-source=auto (default) prefers native hand tracking, then falls back to the controller aim pose. Use controller or hand_tracking to select one source explicitly. Consuming applications read the resulting standard /hand/* stream, so controller mount calibration stays in the device plugin.

The default offsets support PICO 4 Ultra controllers mounted upright on the back of each FFG glove using the RealHand bracket, with mirrored left/right installation. For a different mount, override them with --left-aim-to-wrist=px,py,pz,qx,qy,qz,qw and --right-aim-to-wrist=px,py,pz,qx,qy,qz,qw. Translation is in meters in the aim frame; quaternions use XYZW order. --hand-scale=1.0 adjusts the estimated hand size (supported range 0.5 to 2.0).

In controller mode, the hand becomes inactive if wrist tracking is lost or jumps. Disconnected gloves and stale sensor streams also become inactive.

Hand CTS recording#

After completing calibration, use the unmodified in-tree recorder from a commit pushed to the integration pull request. Build and install the plugin and wheel from that same checkout. Prepare the checker and recording environments as specified in Hand Suite.

The recorder launches plugins without command-line arguments. Set the plugin’s environment defaults in the shell that starts the recorder:

export REALHAND_FFG_GLOVE_CALIBRATION=/absolute/path/to/ffg_human.yml
export REALHAND_FFG_GLOVE_PORTS=/dev/ttyUSB0,/dev/ttyUSB1
export REALHAND_FFG_GLOVE_WRIST_SOURCE=controller
bash src/python/isaaccapture/cts/hand/capture/record.sh realhand_ffg_glove \
  --plugin realhand_ffg_glove_plugin

Only use verified glove ports. Keep WebXR connected and both controllers tracked for controller-sourced wrists. The recorder obtains the source commit and wrist source from the checkout and environment; keep its provenance and generated archive unchanged. Submit the new take following Submit Your Results.

Troubleshooting#

Status or symptom

Resolution

No identified FFG USB device

Verify power and cable. Generic UART adapters require explicit verified ports.

Permission denied

Check serial permissions and dialout membership; log out and back in after group changes.

Serial port is already in use

Close other glove readers and stop any previously launched plugin.

Missing human calibration for this hand

Capture that side, then pass the YAML with –calibration or REALHAND_FFG_GLOVE_CALIBRATION.

No fresh usable skeleton / no position response

Check glove power, USB connection, and the selected baud rates. The plugin reconnects automatically.

Controller wrist unavailable or discontinuous

Keep the mounted controllers visible to the headset; recover stable tracking before recording.

RealHand P7 Dual-Arm Targets
============================

The P7 example consumes controller or standard hand wrists and produces absolute
left/right end-effector targets with the official ``Se3AbsRetargeter`` and
``EePoseRateLimiter``. It contains no glove or finger retargeting.

Install
-------

Install the locally built Isaac Capture package following
:ref:`build-from-source-install-package`, then install this example:

.. code-block:: console

   $ uv pip install -e ./examples/realhand_p7

In-tree installation and tests are optional. Enable them explicitly with
``-DBUILD_EXAMPLE_REALHAND_P7=ON`` when configuring the source build.

Run
---

.. code-block:: console

   $ python -m isaaccapture_examples.realhand_p7.p7_bimanual_example --input-mode controller
   $ python -m isaaccapture_examples.realhand_p7.p7_bimanual_example --input-mode handtracking

The CLI launches CloudXR and prints targets; it does not launch a robot
simulator or command hardware. Use ``--dry-run`` without OpenXR.
A compatible glove can publish the same standard hand stream independently.

Graph Contract
--------------

``build_pipeline(mode)`` returns the graph and action order. Supply
``world_T_anchor`` at each step; ``IsaacTeleopDevice`` provides this transform
when the graph is consumed by Isaac Lab. The CLI defaults to stage +X/right,
+Y/up, -Z/forward mapped to P7 +X/right, +Y/forward, +Z/up. Override the CLI
matrix with ``--world-t-anchor`` followed by 16 row-major values.

The wrist-to-tool rotation is separate from the world anchor. Output is left
XYZ and XYZW quaternion, then right XYZ and XYZW quaternion. The host owns
inverse kinematics, joint limits, collision checking, and robot physics.
The example does not implement an IK solver or hardware driver.

The optional complete simulation application and robot assets are available in
`RealHand Teleop on Hugging Face <https://huggingface.co/realhandinc/realhand-teleop>`_.
They are not required to build this target-pose graph.

# Camera settings

`tools/start_system.py` runs the camera chain from one set of files. This page says which component owns which
setting, what the default profile contains, and what every key does. Edit a copy of the profile for another rig and
pass it with `--sender-config`.

## Who owns which setting

| Component | Owns | Where it is set |
|---|---|---|
| SIPL platform file | Sensor geometry, sensor rate, trigger mode, link wiring | `sipl.platform_config_json` on the Orin (installed by the BSP or the camera deploy) |
| Sender (Orin) | Output frame rate and bitrate, codec, timing records, clock responder, TCP port | The sender profile, `configs/default-camera-settings.yaml` |
| Receiver (PC) | Decoding, the CUDA IPC output and its stream names | Generated by the launcher from the sender profile |
| Bridge (PC) | Publishing into LiveKit; timestamp basis; the sender-clock address; output rate | Command-line flags, built by the launcher |
| CaptureServer | The stream descriptors the page reads (room, track, size, nominal fps, timestamp basis) | Generated by the launcher |

The sender never reads exposure, gain, white balance, trigger frequency or clock-pin settings from its YAML, and there
is no runtime settings API: add such keys to the file and nothing happens.

## The default sender profile

`configs/default-camera-settings.yaml` is the profile the launcher uses unless told otherwise. It describes one SHW5G head
camera on the SIPL backend: HEVC at 30 fps and 4 Mbit/s,
the AVS1 timing extension on, and the UDP clock responder on port 5611.

The file is specific to that rig. A different SIPL platform or camera changes the `sipl` block (platform file, config
name, link masks, tuning directory) and possibly the stream id and size. The Argus backend has no `sipl` block: it
selects a sensor mode with `cameras[].mode`, can set `capture.mode` and `alignment`, enforces `output.fps` with a rate
limiter and can set output dimensions. Keep one file per rig and pass the right one with `--sender-config`. The launcher itself supports one stream per
file and requires `network.timing_extension: true`, `network.clock_port` and an explicit `output.fps`.

`tools/start_system.py` loads this file by default. Command-line overrides (`--fps`, `--bitrate-mbps`,
`--clock-port`, `--sender-port`) are applied to the loaded mapping, and the result is what is uploaded. The same
values feed the bridge and the CaptureServer descriptor, so they cannot disagree.

### How the file reaches the sender

The sender does not search for a camera file. The deploy tool uploads the chosen file over SSH to
`~/camera-streamer/releases/RELEASE/src/configs/run-config.yaml` on the Orin, beside the shipped configs so paths in
it that are relative to the file (the remaps) resolve inside the release, and starts `./build/argus_sender --config
src/configs/run-config.yaml`. The file is read once at start. Editing it while the sender runs changes nothing: stop the
sender and start it again. A reconnecting receiver reuses the same in-memory configuration. Uploading a new file does
not rebuild the binary, so the release must already support the timing extension and the clock responder; an older
parser rejects keys it does not know instead of ignoring them. The platform JSON and tuning files are not uploaded
and must already exist at the configured paths on the Orin.

### Frame rate

`streams[].output.fps` defaults to `0`, which resolves the native rate (SIPL: the platform file's virtual-channel
rate). A nonzero value is used instead. All streams must use native rates together or explicit rates together.

On the SIPL backend `output.fps` sets the encoder's rate, the default GOP length and the rate advertised in AVS1, and
the sender skips frames that arrive sooner than 85 % of that period after the last one sent, so a 60 Hz sensor gives a
30 Hz stream. It does not program the sensor trigger. The Argus backend selects output frames with its own rate
limiter. The sender's `@ N FPS` startup line prints the resolved setting; it is not a measured
rate. The receiver's `decode[avs1]` line is measured.

The bridge's `--fps` and the descriptor's `fps` are separate settings. The launcher sets both from the sender's
effective `output.fps`; the descriptor value is nominal and cannot make the camera faster.

### Latency

The page shows latency from the sensor's capture time only when all of these hold:

1. The sender runs with `network.timing_extension: true` and `network.clock_port` set (the default profile does both),
   from a release that includes the timing extension and the clock responder.
2. The receiver passes the timing records through to the CUDA IPC output.
3. The bridge runs with `--timestamp-basis capture_monotonic_us --sender-clock ORIN_HOST:CLOCK_PORT`. For a SIPL profile
   the launcher also passes `--source-full-range`, because SIPL pictures use the full 0-255 range; without it the
   encoded stream signals limited range and the page's blacks and whites are wrong. The bridge binary must support
   that flag.
4. The CaptureServer descriptor declares `timestamp_basis: capture_monotonic_us`.
5. The bridge answers the browser's clock exchange, so the page can map the publisher's clock onto its own.

These settings fix what the timestamps mean; they do not reduce the actual delay. Delay depends on the bitrate
against the link, queues in the kernel and the application, and encoder and decoder throughput. When a stamp is
missing, timing is unqualified or the mapping has not settled, the page shows no figure instead of a guess.

## Sender profile keys

These keys belong to the sender release the profile targets, which is not part of this tree: it supports the SIPL
backend and the timing extension. An older `argus_sender` in this repository has a different parser and rejects some
of these keys, so check a release's parser before using a key. Defaults are that parser's own and can differ from the
shipped profile.

| Key | Default / requirement | Meaning and consumer |
|---|---|---|
| `version` | `1`; only 1 accepted | Sender configuration version. |
| `capture_backend` | `auto` | `argus` or `sipl` selects the backend. `auto` works only when exactly one is built; both built requires explicit selection. |
| `sipl` | Optional mapping | SIPL platform inputs below; required values must be present for an explicitly selected SIPL backend. |
| `sipl.platform_config_json` | Empty; required for SIPL | Path on the Orin, loaded by SIPL's query API. Sensor geometry/rate and driver platform selection come from this separate JSON. |
| `sipl.platform_config_name` | Empty; required for SIPL | Named platform inside the database/JSON. |
| `sipl.link_masks` | Empty; required for SIPL | Sequence of unsigned masks, one per deserializer in transport order; passed to `ApplyMask`. Not an FPS knob. |
| `sipl.nito_dir` | `/var/nvidia/nvcam/settings/sipl` | ISP tuning directory; loads `<module-name>.nito` on the Orin. Not a YAML sensor-mode selector. |
| `sipl.isp0_buffers` | `6`; at least 2 | Number of ISP0 surfaces allocated/registered per sensor. Surface ownership and return timing affect pressure; increasing the count does not directly select FPS. |
| `network.bind` | `0.0.0.0`; nonempty | Sender TCP listening address; also used by the timing UDP responder, whose inspected implementation requires IPv4. |
| `network.port` | `5000`; 1–65535 | AVS1 TCP listening port. Receiver must connect here. |
| `network.reconnect_ms` | `1000` | Retry delay for failed listen setup. Not a per-frame sleep or FPS limiter. |
| `network.dump_wire` | Empty / disabled | Writes the transmitted framed stream to a diagnostic file on the sender. Avoid enabling by default; storage can add work. |
| `network.send_buffer_kb` | `0` | Kernel TCP send-buffer request in KiB. Zero leaves OS behavior; positive values set `SO_SNDBUF`. Bounds one source of hidden buffering. |
| `network.timing_extension` | `false` | Emits AVS1 sensor timing qualification records; use `true` for the capture-time chain. Requires a compatible sender and receiver. |
| `network.clock_port` | `0` / disabled | UDP clock-exchange responder; 1–65535 enables it. Use 5611 in this profile and the same port in the bridge's sender-clock address. |
| `runtime.frames` | `0` / unlimited | Finite run limit. Argus counts bundles; SIPL counts successful frame submissions across streams. Not a time duration or FPS setting. |
| `runtime.kpi` | `true` | Enables periodic KPI collection/reporting; detailed output also depends on `--verbose`. |
| `runtime.log_interval_s` | `1` | Periodic logging interval in seconds; zero disables interval-based summaries at sites guarded by a positive interval. |
| `runtime.bench_encode` | `false` | Queue-to-encoded-output callback timing samples and summary. Diagnostic logging may be voluminous. |
| `alignment.warmup_frames` | `60` | Argus startup frame discard for alignment. SIPL's independent mono sender does not consume this setting. |
| `alignment.interval_frames` | `60` | Argus periodic reacquisition cadence; zero disables it. Inactive with continuous FIFO alignment. Not consumed by the SIPL path. |
| `streams` | Required nonempty sequence | Logical output streams. IDs and camera assignments must be unique. |
| `streams[].id` | Required nonempty string | Logical stream label used by the sender. |
| `streams[].type` | Required: `mono` or `stereo` | Requires one or two camera entries respectively. Current SIPL supports mono HEVC only. |
| `streams[].cameras[].device` | Required unsigned integer | Argus device index or SIPL pipeline ID, depending on backend. A device cannot be assigned to multiple streams. |
| `streams[].cameras[].mode` | `0` | Argus sensor-mode index; stereo entries must match. SIPL parses it but uses platform configuration instead. |
| `streams[].capture.mode` | `mailbox` | Argus `mailbox` or `fifo` acquisition. The priority stream requires mailbox in this implementation. SIPL uses its own newest-frame mailbox and does not apply this field. |
| `streams[].capture.fifo_length` | `3` | Argus FIFO depth, at least 3 when FIFO is selected. Supplying it with mailbox is rejected. More queued frames can increase age. |
| `streams[].output.fps` | `0` / native nominal | Output/encoder FPS; frames above it are skipped, with backend differences described above. Does not directly program SIPL trigger timing. |
| `streams[].output.codec` | `hevc` | `hevc`/`h265`, or `raw_nv12`/`raw`/`nv12`. SIPL currently accepts HEVC only. |
| `streams[].output.width` | `0` / inferred | Explicit nonzero width must be even. Argus uses output geometry; SIPL permits native dimensions only and rejects scaling. |
| `streams[].output.height` | `0` / inferred | Same constraints as width. |
| `streams[].output.resize_mode` | `strict` | Argus `strict`, `center_crop` or `stretch` geometry handling. SIPL does not implement resizing. |
| `streams[].output.rotation` | `0`; 0 or 180 | AVS1 presentation metadata; receiver applies it. Sender leaves pixels in native orientation. |
| `streams[].output.bitrate_mbps` | `50`; nonzero for HEVC | Integer Mbps per encoder, passed to NVENC CBR setup. Explicitly use 4 for the constrained-link head profile. Raw NV12 is not bitrate-controlled. |
| `streams[].output.gop` | `0` / resolved FPS | I-frame and requested IDR interval in frames. NVENC's optional IDR control can warn and continue if unsupported. |
| `streams[].output.remap.file` | Empty / disabled; required key if mapping supplied | Argus mono raw-NV12 remap lookup file. Relative paths resolve against sender YAML directory. Not supported by SIPL. |
| `streams[].output.remap.capture_width` | `0`; nonzero even when remap enabled | Source capture geometry for remap; explicit output dimensions and `resize_mode: strict` also required. |
| `streams[].output.remap.capture_height` | `0`; nonzero even when remap enabled | Source capture height for remap. |

## Receiver keys

The receiver reads its own file once at start; the launcher generates it from the sender profile and the stream size.

| Key | Default / requirement | Meaning |
|---|---|---|
| `receiver.host` | `127.0.0.1` | Orin sender address. Override precedence: `--host`, `CAMERA_RECEIVER_HOST`, YAML, default. |
| `receiver.port` | `5000` | Sender TCP port. Override precedence: `--port`, `CAMERA_RECEIVER_PORT`, YAML, default. |
| `receiver.gpu_id` | Unset/null | Optional nonnegative CUDA GPU selection; `--gpu-id` takes precedence. |
| `receiver.max_record_bytes` | `268435456` | Maximum accepted wire record bytes; defensive size bound, not a latency target. |
| `receiver.stats_log_interval_s` | `5.0` | Periodic measured decode/FPS/timing summaries; 0 disables. CLI `--stats-log-interval-s` takes precedence. |
| `receiver.log_timing` | `true` | Legacy fallback only when explicit stats interval is absent; false disables summaries. |
| `receiver.receive_fps_warning_threshold` | `0.0` / disabled | Warn when measured per-stream receive FPS falls below this value; does not change FPS. A profile may use 48 for a 60 FPS target. |
| `receiver.receive_fps_warning_interval_s` | `10.0` | Warning measurement/report interval; must be positive when warnings enabled. |
| `ipc.socket_path` | `/tmp/camera_receiver_avs1_cuda_ipc.sock` | Local Unix socket for CUDA IPC consumers; `--socket` overrides. Must match bridge input socket. |
| `ipc.owner_name` | `camera_receiver_avs1` | CUDA IPC producer identity. |
| `ipc.queue_size` | `1024` | Publisher control/notification queue capacity; not an Orin TCP setting. |
| `streams` | Required nonempty sequence | Receiver stream descriptions; generated IPC names must be unique. |
| `streams[].index` | Required integer | Stream position/index matching AVS1 stream records. |
| `streams[].name` | `stream<index>` | Local name, used to derive IPC names. |
| `streams[].type` | `mono`, or `stereo` if legacy flag true | Describes stream topology. |
| `streams[].stereo` | Derived from `type` | Legacy explicit stereo flag; avoid conflicting declarations. |
| `streams[].width` | Required integer | Wire frame width before receiver display rotation. Match actual sender output. |
| `streams[].height` | Required integer | Wire frame height. |
| `streams[].output_format` | `nv12` | `nv12` or `rgba8` CUDA output. Use NV12 for the GPU bridge path. |
| `streams[].ring_depth` | `6`; at least 3 | Receiver output surface ring depth. Not an FPS limiter or sensor buffer count. |
| `streams[].full_range` | `false` | Receiver color-range handling. Match wire/source semantics; not a timing setting. |
| `streams[].ipc.mono` | Stream name | IPC output name for a mono stream. Bridge must select this name. |
| `streams[].ipc.left` | `<name>.left` | IPC name for stereo left eye. |
| `streams[].ipc.right` | `<name>.right` | IPC name for stereo right eye. |

The sender and receiver files are separate schemas: the sender release described here rejects the `receiver` and `ipc` roots, and receiver
stream entries need fields such as `index` that the sender does not have.

## CaptureServer stream descriptor keys

`capture-server --livekit-streams FILE` reads this file. It tells clients where the video is and how to read its
timestamps; it does not configure the Orin or join LiveKit for anyone.

| Key | Default / requirement | Meaning |
|---|---|---|
| `livekit.url` | Required valid descriptor value | LiveKit server URL reachable by each consumer. Loopback is suitable only for consumers on the same machine. |
| `livekit.room` | Required valid descriptor value | Room the bridge publishes into. |
| `livekit.publisher` | Required valid descriptor value | Bridge publisher identity. Must match actual publisher. |
| `livekit.timestamp_basis` | `monotonic_us` | Timestamp meaning. Accepted names: `monotonic_us`, `processing_unix_us`, `capture_unix_us`, `capture_monotonic_us`. This chain requires `capture_monotonic_us`. |
| `livekit.streams` | Required list | Descriptors; underlying protocol validation checks values/duplicates. |
| `livekit.streams[].name` | Required valid descriptor value | User-facing logical camera name. |
| `livekit.streams[].track` | Required valid descriptor value | Actual LiveKit track name published by bridge. |
| `livekit.streams[].width` | Required valid descriptor value | Advertised image width; match processed output. |
| `livekit.streams[].height` | Required valid descriptor value | Advertised image height. |
| `livekit.streams[].fps` | Required valid descriptor value | Advertised nominal FPS; the launcher sets it to the sender's effective `output.fps`, and it does not command the sender. |
